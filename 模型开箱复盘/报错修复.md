## 1. 基础配置与双接口功能验证

**验收依据：**按 [官方 model-rl-case-guard v0.23.0](https://github.com/yeyunu/step5-model-openbox/blob/main/step5%E5%BC%80%E7%AE%B1%E4%BA%A4%E4%BB%98%E4%BB%B6-%E9%99%84%E4%BB%B6/%E5%85%AB%E5%B1%82%E9%87%8D%E6%9E%84%E5%A4%8D%E9%AA%8C/official-skill/SKILL.md) 的基础配置与双接口功能要求检查服务响应、文本及 token/logprob 数据。非空和有限值属于公共验证器的检查条件；本节不把它们另列成一个开箱特性。正式项目清单、上游版本和状态见 [交付件第 1 节](https://github.com/yeyunu/step5-model-openbox/blob/main/%E6%A8%A1%E5%9E%8B%E5%BC%80%E7%AE%B1%E5%A4%8D%E7%9B%98/step5%E5%BC%80%E7%AE%B1%E4%BA%A4%E4%BB%98%E4%BB%B6.md#1-%E9%AA%8C%E6%94%B6%E4%BE%9D%E6%8D%AE%E4%B8%8E%E7%BB%93%E8%AE%BA%E6%80%BB%E8%A7%88)。

**处理：**从现存首尾十六层父 checkpoint 重构原层 `[0,1,2,3,88,89,90,91]`，重映射层号与配置；逐张量比对父模型归档 hash，并回读目标核验。得到 802 tensors、13 shards、58.242456 GiB 的真实 BF16 权重。

**复验：**固定 4 条 prompt 和采样配置，8/32 token 两组的 completions、chat/completions 均各 4/4 通过，`endpoint_checks` 均为 true；共 16 条响应、320 个 token/logprob 对，数量一致且 logprob 均为有限数值。结论是本轮双接口功能探针 `passed`。文本未见 Unicode 替换字符，但含词片段和重复词；不据此认定语义或精度正常。上游标准 curl 示例原样执行记录未归档，单独记为 `not_run`。

## 3. IPC 资源释放与内存观测

**上游通过条件：**加载真实目标 checkpoint，在 sleep(level=2) → wake(weights) → update → wake(kv_cache) 后，同一接口、同一 prompt 的 text、tokens、token_logprobs 必须与基线逐项完全一致。

**本轮结果：**8 个同卡 producer 完成一次真实 IPC 权重更新，max_tokens=8。completions 的 4 对、chat/completions 的 4 对响应均满足文字完全相同、token 序列逐项相同、logprob 数值逐项相同；`outputs_identical_by_endpoint` 两组均为 `[true,true,true,true]`，客户端退出 0。原始报告 `passed` 对应首轮输出幂等一致性，不能扩写为 HCCL、Checkpoint reload 或多轮稳定性通过。

schema 取证覆盖 8 worker；参数及 allocator 观测仅覆盖 DP0 四个 worker。每 rank 抽样 766 个参数的首/中/末元素，并非全量权重校验。

仍存在两项待验证现象：

- 客户端 8 条 `Producer process has been terminated before all shared NPU tensors released` 警告。
- DP0 每 rank allocated 均为 24.9351 GiB；reserved 从 27.4570 增至 45.6035 GiB，增加 18.1465 GiB。

225 连续两轮的观测中，reserved 首轮增加后第二轮保持不变，输出一致性通过；共享张量释放告警仍待定位，长期内存稳定性尚未验证。
